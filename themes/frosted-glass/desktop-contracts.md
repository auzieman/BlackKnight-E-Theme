# Frosty desktop integration — next boundary

User selected Frosty as an E desktop theme direction on 2026-10-15. Native first
assembly lives in the independent control-centre preview; that application's
workstation/main group is not an Enlightenment desktop theme entrypoint.

The approved direction is a smaller truncated-triangle title cap, matching
window actions and shelf edges, off-white readable content and optional neutral,
Glacier Blue and Mint tints. Keep layout/material separate from the selected hue.
Hue previews currently affect the standalone app only; no E colour settings are
saved. The code-native SVGs are original first-pass components, not crops of the
AI concept and not replacements for the existing blue-steel assets.

Before a desktop candidate: trace e/widgets/border/default/border and the selected
e/shelf groups against the installed E27 source and known-working theme. Preserve
client swallow, title/icon parts, focus/urgent/maximized/shaded states, drag and
resize hit regions, close/minimize/maximize/menu signals and shelf orientations.
Map Frosty materials to those real contracts or use a scoped override with the
known-working fallback. A standalone frame screenshot is not proof of those
contracts. Do not repeat unrelated donor source repairs to force a build.

Build and render the chosen groups standalone via BKC first, then use the existing
protected desktop-trial workflow for a selected candidate. Whole-theme widget
coverage, contrast, wallpaper/compositor and packaging remain separate evidence.
Do not install this material preview as a complete E theme.
